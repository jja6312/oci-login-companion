# OCI Login Companion

처음 실행하면 **로컬 저장소 / 팀 공유 파일**을 선택합니다. 팀 파일은 **새 파일 만들기 / 기존 파일 선택**으로 바로 연결하며, 별도 편집 허용 체크 없이 추가·편집·삭제·일괄 등록·가져오기를 그 파일에 저장합니다. 브라우저 자체의 파일 쓰기 승인은 필요합니다. 기존 사용자의 계정·테마·저장 위치는 보존하며 첫 실행 선택을 다시 띄우지 않습니다.


Chrome과 Brave에서 테넌시를 검색해 OCI 로그인을 시작하는 브라우저 확장입니다.

**[Install.cmd 다운로드](https://github.com/jja6312/oci-login-companion/releases/latest/download/Install.cmd)**

CMD 하나로 처음 설치와 기존 관리형 설치 업데이트를 처리합니다. Python과 관리자 권한은 필요하지 않습니다.
파일을 준비한 뒤 **실제 화면과 빨간 박스로 된 안내**를 엽니다. 탐색기 폴더는 자동으로 열지 않습니다.

## 처음 설치

안내의 **폴더 경로 복사**를 누른 뒤 확장 관리에서 개발자 모드를 켭니다.
**압축해제된 확장 프로그램 로드**를 누르고 폴더 선택 창에 경로를 붙여넣습니다.
마지막으로 **세부정보 → 시크릿 모드에서 허용**을 켜세요.

## 기존 사용자

설치했던 **같은 브라우저와 같은 프로필**에서 기존 카드의 새로고침을 누릅니다.
같은 확장 폴더를 유지하므로 기존 계정과 설정을 계속 사용합니다. 카드를 삭제하거나 새로 추가하지 마세요.
확장 파일과 업데이트 영수증은 백업하며, 사용자가 수정한 설치는 덮어쓰지 않습니다.

## 사용

**Ctrl+Shift+Space**로 열고 테넌시를 검색합니다. 계정, 사용자, 비밀번호와 Bypass Code를 등록할 수 있습니다.
Excel에서 복사한 여러 행의 일괄 등록, 고객 별칭, 테마와 시크릿 창을 지원합니다.
확장은 OCI의 확인된 로그인 흐름에서 동작하며 필요한 사이트 접근 권한을 브라우저에서 요청합니다.

개인 계정은 브라우저에, 팀 계정은 사용자가 선택한 공유 JSON 파일에 저장합니다. 배포본과 스크린샷에는 실제 계정이나 인증값이 없습니다.
시크릿 허용은 사용자가 직접 켜야 합니다. 설치기는 브라우저 정책이나 프로필 파일을 수정하지 않습니다.

## 팀 파일과 Brave

팀 파일 연결은 **파일 선택** 한 가지로 통합했습니다. 별도 보조 프로그램은 필요하지 않습니다.
각 PC에 동기화된 같은 OneDrive JSON을 선택하면 바로 편집할 수 있습니다. 브라우저의 파일 쓰기 승인은 사용자가 직접 허용합니다.
이후 연결을 변경할 때만 설정에서 **파일 선택 → 파일 접근 허용 및 저장 위치 적용**을 누릅니다.
개인/팀 목록 가져오기·내보내기는 설정의 데이터 탭에서 대상을 선택합니다.

Brave에서 파일 선택이 비활성이라면 설정의 **Brave 설정 열기**를 누르거나 `brave://flags/#file-system-access-api`를 열어
**File System Access API → Enabled → Relaunch**를 한 번 진행하세요. 확장이 브라우저 설정을 자동 변경하지는 않습니다.
이전 전체 경로 연결은 같은 JSON을 파일 선택으로 다시 연결합니다. 개인 목록·테마와 기존 파일 선택 연결은 유지합니다.
파일은 목록 열기와 로그인 시작 때 다시 읽으며, 다른 PC에는 OneDrive 동기화가 끝난 뒤 반영됩니다.

## Prisma Browser

Palo Alto Networks **Prisma Browser 데스크톱**용 설치 안내를 추가했습니다. 설치 도우미에서 Prisma를 선택하고 `prisma://extensions/`에서 같은 extension 폴더를 등록합니다. 기존 등록은 새로고침합니다.
조직의 확장 허용·개발자 모드·파일 접근 정책이 허용해야 합니다. 파일 선택이 차단되면 관리자 확인 안내를 표시하고 기존 목록을 보존합니다.
실제 Prisma 실행 파일과 사용자 조직 정책에서의 검증은 별도이며, [설치·정책·검증 범위](docs/PRISMA-BROWSER.txt)를 참고하세요.
브라우저별 개인 저장소는 분리됩니다. 기존 개인 목록은 내보내기/가져오기를 사용하고, 팀 목록은 같은 JSON을 다시 연결합니다.

## 개발

```powershell
node --test tests/*.test.mjs
python scripts/build_visual_guide.py
python scripts/build_visual_installer.py
python -m unittest discover -s tests -p test_visual_installer.py -q
```

일반 빌드는 Python 표준 라이브러리만 사용합니다. 화면 재촬영과 브라우저 보존 시험에는 Playwright가 필요합니다.
현재 앱은 **1.3.5**, 설치기는 **r14**입니다. 기존 GitHub1.3.0r9·1.3.1r10·1.3.2r11·1.3.3r12·1.3.4r13 및 관리형 설치에서 같은 경로로 업데이트합니다.
전달 폴더의 최상위에는 `Install.cmd`만 두고 ZIP과 개발 자료는 `_support`에 보관합니다.
실제 사용자 OCI 인증과 브라우저의 수동 등록 완료는 자동 시험의 범위에 포함하지 않습니다.
기존 버전 검증 스크립트는 `tests`와 `windows`에 보존했습니다.

1.3.5 기능 검증은 [검증 자료](docs/validation-1.3.5.json)에 기록했습니다. Brave Linux의 실제 파일 핸들 검사와 Windows 설치 CI는 구분합니다. 실제 사용자 OneDrive 클라우드 전송과 고객 OCI 인증은 자동 시험으로 보장하지 않습니다.

앞으로 이 저장소의 `main`과 최신 `Install.cmd` 릴리스를 함께 갱신합니다.

팀 파일 권한이 일회성이면 팝업을 닫은 뒤 만료될 수 있습니다. 이제 설정을 다시 적용하지 않고 메인 화면의 **팀 파일 열기** 또는 Enter로 기존 연결을 복구합니다. 승인 창에서 **방문할 때마다 허용**이 보이면 선택하세요. 이미 유지된 권한은 자동 사용하고, 권한이 없는 상태에서 이전 암호로 대신 로그인하지 않습니다. 확장은 브라우저 승인을 자동 선택하거나 보안 설정을 변경하지 않습니다.

팀 파일 열기를 Enter로 승인하면 상단 테넌시 검색창으로 포커스를 옮깁니다. 설정에서는 **파일 접근 허용 및 저장 위치 적용** 한 번으로 권한 확인과 연결 적용을 처리하고, 성공하면 설정을 닫아 바로 검색할 수 있습니다.
