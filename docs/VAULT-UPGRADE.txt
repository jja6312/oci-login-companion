OCI Companion 2.0 — 암호화 금고로 이전

1. Windows 업데이트
기존 Install.cmd를 실행하고 같은 브라우저·프로필의 기존 확장 카드를 새로고침합니다.
버전 2.0.0을 확인하세요. 새 유휴 상태 감지 권한은 자동 잠금용이며 브라우저에서 직접 승인합니다. 카드를 삭제하거나 새 폴더를 등록하지 마세요.
설치기는 브라우저 프로필·개인 목록·팀 파일을 복사하거나 변경하지 않습니다.
금고 암호는 확장 화면에서 직접 설정합니다. 채팅이나 GitHub에 보내지 마세요.

2. 개인 금고
처음 열 때 12자 이상의 금고 암호와 확인을 입력합니다.
가능하면 16자 이상의 무작위 암호나 긴 문장형 암호를 쓰고 Bitwarden 등 별도 금고에 보관하세요.
암호를 분실하면 복구할 수 없습니다. 서버나 숨겨진 복구 키는 없습니다.
기존 개인 목록이 있으면 먼저 암호화하고 읽어 검증한 뒤 profiles 평문 저장값을 제거합니다.
실패하거나 다른 창에서 목록을 바꾸면 원본을 보존하며, 자동으로 빈 목록을 덮어쓰지 않습니다.
팀 모드라도 브라우저에 남아 있는 기존 개인 평문 목록부터 보호합니다.

3. 팀 금고
기존 파일 연결을 유지합니다. 파일 접근 승인은 브라우저에서 직접 허용해야 합니다.
개인 암호와 다른 팀 금고 암호를 설정하고 팀원에게 파일과 별도 경로로 전달하세요.
기존 평문 팀 파일은 쓰기 승인을 받은 후 같은 파일 안에서 암호화 형식으로 바꿉니다.
데이터를 검증하고 변경 충돌을 확인한 뒤 쓰며, 자동으로 평문 백업을 만들지 않습니다.
팀원 모두 2.0 이상으로 업데이트해야 합니다. 구버전은 암호화 파일을 열 수 없습니다.
기존 백업·내보낸 JSON·OneDrive 버전 이력·디스크의 삭제 흔적까지 안전 삭제하지는 않습니다.
암호화 이전의 사본이 우려되면 OCI 관리자와 비밀번호·Bypass Code 교체를 별도로 진행하세요.

4. 열기와 잠금
금고 암호를 입력하고 Enter를 누르면 상단 테넌시 검색창으로 돌아옵니다.
암호는 저장하지 않습니다. 복호화 키는 chrome.storage.session의 브라우저 메모리에만 보관합니다.
일반 팝업을 닫았다 다시 여는 동안은 유효한 메모리 키를 재사용합니다.
브라우저 재시작·확장 새로고침/업데이트·수동 잠금·확장에서 5분 미사용 시 잠깁니다.
지원되는 데스크톱에서는 기기 잠금/유휴 상태도 감지합니다. 플랫폼별 감지는 다를 수 있습니다.
자물쇠 버튼 또는 확장을 연 상태의 Alt+L로 지금 잠글 수 있습니다.
잠그면 목록·표시된 값·편집/가져오기 초안·메모리 키와 진행 중 로그인 작업을 정리합니다.
이미 Oracle 페이지에 입력했거나 로그인한 세션은 자동 로그아웃하지 않습니다.

5. 가져오기와 내보내기
내보내기는 암호화된 .vault.json 파일입니다. 현재 금고 암호로 열 수 있습니다.
다른 금고의 파일을 가져올 때는 그 파일의 암호와, 가져올 대상 금고의 잠금 해제가 필요합니다.
예전 평문 JSON도 가져올 수 있지만 원본 파일은 그대로 남습니다.
Excel 일괄 등록과 계정 추가/편집도 암호화한 상태로만 저장합니다.
비밀번호·코드의 복사 버튼을 사용하면 OS 클립보드와 클립보드 이력에 값이 남을 수 있습니다.
자동 로그인 자체는 클립보드를 사용하지 않습니다.

6. 금고 암호 변경
설정 → 금고에서 현재 암호와 새 암호를 입력합니다.
데이터 키도 새로 발급하고 전체 내용을 다시 암호화한 뒤 모든 금고를 잠급니다.
팀원은 동기화된 최신 파일과 새 암호로 다시 열어야 합니다.
팀원 제외는 OneDrive 접근 권한도 함께 회수해야 합니다.
이미 복사한 OCI 비밀번호·Bypass Code나 이미 로그인한 세션은 금고 암호 변경으로 폐기되지 않습니다.
OneDrive 동기화 완료와 로컬 파일 저장은 별개이며, 여러 PC 사이의 충돌을 완전히 방지하지 못합니다.

7. 보호 범위
AES-256-GCM과 PBKDF2-HMAC-SHA-256 600,000회를 브라우저 Web Crypto로 사용합니다.
파일마다 무작위 솔트·데이터 키, 매 암호화마다 새 96-bit IV, 128-bit 인증 태그를 사용합니다.
알고리즘/형식 변경, 손상, 잘못된 암호는 거부합니다. 암호화된 것으로 확인한 팀 연결이
평문이나 빈 파일로 바뀌면 자동 재이전하지 않습니다. 오래된 정상 암호문으로의 롤백까지 검출하지는 않습니다.

저장 파일만 유출된 상황의 보호를 강화합니다. 잠금 해제 중 감염된 기기, 악성/변조된 확장,
Oracle 페이지 입력값을 읽을 권한이 있는 악성 스크립트, 약한 금고 암호까지 해결하지는 못합니다.
운영체제의 스왑·메모리 덤프, 브라우저 자체 비밀번호 저장과 다른 사본도 별도 관리 대상입니다.
팀 공유 암호를 아는 사람은 금고 전체를 열 수 있습니다. 사용자별 권한·감사 서버는 없습니다.
무기한·무제한 Bypass Code의 운영 위험은 암호화 후에도 남습니다.
이 구현은 독립된 제3자 보안 감사를 받은 상용 금고라는 보증이 아닙니다.

8. Android Brave Nightly
같은 2.0.0 코드로 만든 별도 시험 CRX/ZIP을 사용하세요. Windows CMD는 실행되지 않습니다.
기존 시험 CRX와 같은 서명 ID를 유지합니다. 기존 카드를 삭제하면 그 브라우저의 금고가 제거될 수 있습니다.
Android 실기기 설치·권한·OneDrive 문서 공급자·시크릿·OCI 로그인은 별도 검증이 필요합니다.
실험 브라우저를 실제 고객의 장기 Bypass Code 보관·로그인 용도로 검증 완료했다고 보지 마세요.
