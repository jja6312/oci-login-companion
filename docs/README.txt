OCI Companion 1.2.2 · 2026-11-22

설치
1. OCI-Login-Companion-v1.2.2.zip을 고정된 폴더에 압축 해제합니다.
2. Chrome에서 chrome://extensions 를 열고 개발자 모드를 켭니다.
3. '압축해제된 확장 프로그램을 로드합니다' → 패키지 안의 extension 폴더를 선택합니다.
4. 퍼즐 아이콘에서 OCI Login Companion을 고정합니다.
설치 후 이 폴더를 옮기거나 삭제하지 마세요. 기존 설치를 갱신할 때는 먼저 JSON으로 백업하고 같은 확장 경로를 유지한 채 파일을 교체한 뒤 '새로고침'을 누르세요. 다른 경로로 설치하면 확장 ID와 저장소가 달라질 수 있습니다. 열려 있던 OCI 탭도 새로고침해 주세요.
이 배포본은 Chrome 개발자 모드용입니다. 스토어 게시와 실제 PC 설치는 완료하지 않았습니다. webstore ZIP은 향후 제출 준비용입니다.

기존 설치 도우미 사용자 업데이트
Windows Update r6 CMD를 실행하고, 원래 사용하던 브라우저·프로필의 기존 OCI Login Companion 카드에서 새로고침을 누르세요. 확장을 삭제하거나 새 경로로 추가하지 마세요. 같은 extension 경로를 유지하며 이전 파일은 로컬 백업으로 보관합니다. 직접 다른 폴더에 설치했다면 그 기존 extension 폴더에 이번 ZIP의 extension 내용만 교체하고 새로고침하세요.

개인용: 네 가지 값으로 시작
상단 +를 눌러 테넌시 이름, 아이디, 비밀번호, 관리자가 발급한 Bypass Code를 저장합니다. 추가 설정에서 계정 별칭과 Identity Domain(Default 기본값)을 지정할 수 있습니다. 웹사이트 URL을 등록할 필요는 없습니다. 재사용 가능 여부와 만료 여부는 Oracle 관리자가 설정한 코드의 속성을 따릅니다. 이 확장 프로그램이 코드를 생성하거나 만료를 해제하지 않습니다.

Ctrl + Shift + Space → 테넌시 검색 → Enter.
새 탭에서 OCI 테넌시 → Identity Domain → 아이디·비밀번호 → Show alternative login methods(다른 인증 방법) → Bypass Code → 코드 입력 → 제출 순서로 처리합니다. ↑ ↓로 검색 결과를 선택할 수 있고, 오른쪽 로그인 버튼도 같은 동작입니다. Mac은 Command + Shift + Space입니다. 변경: chrome://extensions/shortcuts.

최초 실행 시 Chrome의 OCI 접근 요청을 허용해 주세요. cloud.oracle.com, login.oci.oraclecloud.com, www.oracle.com/cloud/sign-in.html과 Oracle의 Identity Domain 주소 범위에 대한 선택적 권한을 요청합니다. 실제 비밀값은 진행 중인 로그인 탭의 확인된 인증 주소에만 제공합니다. 테넌시를 입력한 콘솔/Oracle 로그인 게이트웨이에서 이어진 인증 주소를 확인하고, 로그인 완료 후 그 연결 정보를 이 브라우저에 저장합니다. 계정의 테넌시·사용자·도메인이 바뀌면 새 연결로 확인합니다. 일반 웹사이트나 다른 브라우저 탭에 비밀값을 입력하지 않습니다.

우측 ··· → 현재 탭에 입력만: 해당 계정으로 한 번 확인된 OCI 인증 탭에서 입력란만 채우고 제출하지 않습니다. 다른 인증 방식 선택과 페이지 이동은 직접 합니다.

테마 설정
왼쪽 위 메뉴 → 화면에서 다크·라이트·시스템 밝기와 테마색을 선택합니다. 여섯 색 프리셋과 직접 고르기를 제공합니다. 설정은 현재 브라우저에 보관하며 팀 JSON과 별개입니다.

팀 파일: 파일 선택
1. 설정 → 데이터에서 계정을 JSON으로 내보내거나 예제 파일을 받습니다.
2. 기존 공유폴더/Nextcloud에 JSON 파일을 보관합니다.
3. 설정 → 저장 위치 → 팀 파일 → 파일 선택으로 그 파일을 연결합니다.
4. 저장 위치 적용 → 연결 확인을 누릅니다.
각 팀원은 자신의 PC에서 파일에 연결합니다. 확장 프로그램은 파일을 읽기 전용으로 사용하며 계정 편집은 개인 저장소에서 합니다. 목록을 열거나 새로 읽기·로그인 실행 시 현재 파일을 다시 읽습니다. 오류가 있으면 이전 비밀값이나 개인 저장소로 대신 로그인하지 않습니다.
파일 이동이나 동기화 프로그램의 파일 교체로 핸들이 끊기면 같은 파일을 다시 선택하세요. Chrome이 읽기 권한을 요구하면 접근 다시 허용을 누르세요. 공유폴더 동기화는 기존 OS/동기화 프로그램이 처리합니다. 확장 프로그램이 자체 서버로 업로드하거나 동기화 설정을 바꾸지 않습니다.

팀 파일: Windows 전체 경로
Chrome 확장만으로 임의 파일 경로를 읽을 수 없으므로 이 방식은 읽기 전용 Windows 보조 프로그램을 사용합니다.
1. chrome://extensions에서 확장 ID를 복사합니다.
2. 패키지 windows/Install.cmd 실행 → 확장 ID와 실제 JSON 전체 경로 입력.
3. 설정 → 저장 위치 → 팀 파일 → Windows 전체 경로 선택.
4. 같은 경로를 입력하고 파일 보조 프로그램 허용을 누릅니다.
5. 저장 위치 적용 → 연결 확인.
현재 사용자 LOCALAPPDATA/Cloudragon/OCILoginCompanion과 HKCU/Software/Google/Chrome/NativeMessagingHosts/cloudragon.oci_login_files에 등록합니다. 지정한 확장 ID와 JSON 한 파일만 허용합니다. 파일 쓰기, 폴더 탐색, HTTP 리스너, 시스템 서비스는 없습니다. ID/경로 변경 시 Install.cmd를 다시 실행하고, 제거는 설치 폴더의 Uninstall.ps1을 사용합니다. 팀 JSON은 삭제하지 않습니다. 회사 실행 정책은 낮추지 말고 파일 선택 방식 또는 승인된 설치 절차를 사용하세요.

가져오기·내보내기
JSON 가져오기는 개인 저장소에 병합합니다. 같은 ID의 내용이 다르면 중지하며 '같은 ID의 계정 갱신 허용'을 선택한 경우만 갱신합니다. 가져오기가 현재 저장 위치를 바꾸지는 않습니다.
내보내기는 현재 저장 위치의 모든 계정을 비밀번호·Bypass Code를 포함해 저장합니다. 팀 파일을 편집하려면 개인 저장소로 가져와 수정 후 새 파일로 내보내고 팀 관리자가 검토해 원본을 교체합니다. 최대 512 KiB/300계정입니다. v1.0/1.1.0 JSON도 가져올 수 있으며 기존 loginUrl 필드는 확인 후 제거됩니다. 계정마다 임의 URL을 열지 않고 항상 OCI 콘솔에서 시작합니다.

저장 범위
개인 인증 정보는 OCI 웹사이트 localStorage가 아닌 확장프로그램 전용 chrome.storage.local에 저장됩니다. Chrome 계정 동기화와 개발자 서버 전송은 사용하지 않습니다. 마스터 비밀번호·자동 잠금·별도 금고 암호화는 제공하지 않으므로 PC/Chrome 프로필과 팀 파일의 접근 권한으로 보호되는 방식입니다.
작업 하나의 비밀값은 최대 3분간 확장 전용 세션 저장소에 보관하며 중지·탭 닫기·완료·만료 시 제거합니다. 절전 중 알람은 기상 후 처리될 수 있지만 만료된 작업은 값을 새로 제공하지 않습니다. 콘텐츠 스크립트는 저장소 전체를 읽을 수 없습니다. 표시·복사는 사용자가 누른 경우만 수행하며, 복사한 값은 OS 클립보드에 남을 수 있습니다.

지원 범위와 중지 시 확인
표준 OCI Identity Domain의 영어/한국어 로그인 화면을 대상으로 합니다. OCI 세션 선택 화면에서는 테넌시·아이디·도메인이 모두 일치하는 세션 하나만 선택합니다. 없으면 다른 사용자 계정 로그인으로 이어집니다. 기존 세션을 로그아웃하지 않습니다. 외부 기업 SSO, CAPTCHA, 비밀번호 변경, 모바일 승인은 직접 처리해야 할 수 있습니다. 다른 인증 주소나 오류/중복 입력란에서는 중지하며 반복 제출하지 않습니다. 추가 설정의 CSS 선택자로 조직별 화면을 조정할 수 있습니다. JSON에서 실행 코드를 받지는 않습니다.

검증 범위
Linux Chromium의 실제 확장 환경에서 모의 OCI 화면을 사용해 검색+Enter 전체 흐름, 동일 고정 코드 재사용, 사용자 지정 도메인 선택, Bypass Code 라디오 방식, 테마 저장, 파일 재읽기와 오류 처리를 검사했습니다. 실제 Oracle 트래픽은 보내지 않았고 테스트 사본만 OCI 권한을 미리 부여했습니다. 실제 OCI 계정 로그인/Windows 설치와 파일 선택기/PowerShell 5.1 Native Messaging/실제 공유폴더 동기화는 미검증입니다. RELEASE-NOTES.txt에 검사 결과를 기록합니다. 캡처는 가상 계정이며 설치 직후에는 계정이 없습니다.

1.2 추가 기능
시크릿 창에서 실행하면 같은 시크릿 창에서 로그인합니다. Chrome/Brave 확장 관리 → OCI Login Companion 세부정보 → 시크릿 모드에서 허용을 최초 한 번 켜세요. 브라우저가 정한 이 허용을 확장이 대신 켜지는 않습니다. 일반 창과 시크릿 창의 OCI 쿠키는 분리되며 저장 계정·테마는 공유합니다. 시크릿 작업의 최근 사용/학습한 인증 연결은 영구 저장하지 않습니다. 시크릿 창이 닫혔으면 일반 창으로 대신 열지 않습니다.

계정 추가/편집의 고객사명·별칭은 기본 항목입니다. 테넌시·고객사명·아이디로 검색할 수 있습니다. 기존 JSON의 name 값을 그대로 사용하므로 기존 계정 별칭도 유지됩니다.

상단 검색창 아래 일괄 등록을 누르고 엑셀의 테넌시, 아이디, 비밀번호, Bypass Code를 각각 한 열씩 같은 행 순서로 복사해 붙여넣으세요. 고객사명과 Identity Domain 열은 선택입니다. 한 줄이 한 계정이며 여러 열/셀 내부 줄바꿈은 이 입력 방식에서 지원하지 않습니다. 필수 열은 같은 행 수여야 하며 빈 셀을 제거해 줄을 당기지 않습니다. 선택 열을 입력하면 그 열도 같은 행 수로 맞추고, 빈 도메인 셀은 Default로 처리합니다. 비밀번호 앞뒤 공백과 코드 앞자리0을 유지합니다(Excel에서 이미 숫자로 변환한0은 복구할 수 없습니다). 목록 확인 → 비밀값 없는 목록 검토 → N개 등록. 중복/오류는 전체 등록을 중지하며 기존 계정을 덮어쓰지 않습니다. 최대300계정/512KiB는 기존 계정과 합친 결과에도 적용됩니다. 팀 파일에 직접 쓰지 않으므로 개인 저장소에서 등록 후 필요한 경우 JSON을 내보내 팀 관리자가 원본을 교체합니다.

검색창 아래 원형 팔레트6개를 누르면 설정창을 열지 않고 테마색이 즉시 바뀌고 저장됩니다. 직접 색 선택/밝기는 기존 설정에서 사용할 수 있습니다.

1.2.1 수정
Oracle JET 바깥 컴포넌트와 실제 내부 입력란의 중복 인식 문제를 수정했습니다.
Oracle JET 입력값을 blur로 확정하고, 입력 뒤 활성화되는 사인인 버튼을 기다린 뒤 한 번만 누릅니다. 한국어 ‘사인인’ 문구와 실제 내부 입력란을 처리합니다. 초기 HTTP 리디렉션과 문서 준비 시점의 실행도 보완했습니다. 일반/시크릿 창의 분리와 기존 target 검증은 유지합니다.

개인 계정이 없는 화면은 설명 문구 없이 ‘계정 추가’ 버튼만 표시합니다. 팝업 또는 계정 관리 페이지에서 Alt+N으로 같은 추가 창을 열 수 있습니다. 이미 다른 대화상자가 열려 있거나 팀 파일을 보는 동안에는 추가 단축키로 새 창을 겹쳐 열지 않습니다. 브라우저 전체 전역 단축키가 아니라 확장 화면에 포커스가 있을 때의 단축키입니다.

1.2.2 지역 인증 중계 수정
실제 경로는 공통 로그인 서버 → 지역 로그인 서버 → IDCS입니다. 이전 버전은 지역 서버를 모르는 인증 주소로 판단해 입력 전에 중지했습니다. 지역 서버는 브라우저 이동만 추적하며 확장 코드를 주입하거나 계정·비밀번호·Bypass Code를 제공하지 않습니다. 지역 호스트 권한을 새로 요청하지 않습니다. 선택한 테넌시를 확인한 상태에서 해당 중계 경로가 이어진 경우에만 IDCS 인증 입력을 허용합니다.

문제가 남으면 계정 오른쪽 ··· → 진단 정보 복사를 누르세요. 버전, 단계, 중지 이유, 주소 분류와 확인 여부만 복사합니다. 계정명·아이디·비밀번호·코드·실제 호스트·전체URL·파일경로는 포함하지 않습니다. 사용자가 누를 때만 로컬 클립보드로 복사하며 자체 서버 전송은 없습니다. 일반 JSON 설정 내보내기는 인증 정보를 포함하는 별도 기능입니다. 버전은 팝업 왼쪽 아래에도 표시합니다.
