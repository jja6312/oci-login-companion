OCI Companion 1.3.3 — 개인 목록과 팀 파일

팀 공유 시작
1. 처음 실행할 때 팀 공유 파일을 선택합니다.
2. 새 파일 만들기로 팀이 사용하는 OneDrive 폴더에 빈 JSON을 만들거나,
   기존 파일 선택으로 이미 있는 팀 JSON을 연결합니다. 비어 있지 않은 파일은 새 파일 만들기로 덮어쓰지 않습니다.
3. 연결하면 바로 목록을 표시하고 편집 가능합니다. 별도 편집 체크나 저장 위치 적용은 없습니다.
   브라우저가 요청하는 파일 쓰기는 허용해야 합니다. 거부하면 실제 파일을 쓰지 않습니다.
4. 팀원도 각자의 PC에 동기화된 같은 OneDrive JSON을 선택합니다.
   파일 연결은 브라우저에 보관되고 팀 계정은 개인 목록으로 자동 복사되지 않습니다.
개인용은 첫 화면에서 로컬 저장소를 선택합니다. 기존 사용자의 설정은 유지합니다.
나중에 저장 위치를 바꿀 때는 설정 → 저장 위치에서 파일을 선택하고 저장 위치 적용을 누릅니다.

목록 내보내기/가져오기
설정 → 데이터에서 가져올 위치와 내보낼 위치를 각각 개인 저장소 또는 연결된 팀 파일로 선택합니다.
내보내기는 해당 위치를 새로 읽어 JSON으로 저장합니다. 비밀번호와 Bypass Code가 포함됩니다.
가져오기는 기존 계정을 보존하며 합칩니다. 같은 ID의 값을 바꾸려면 ‘같은 ID의 계정 갱신 허용’을 켭니다.
팀 대상 가져오기와 편집·추가·삭제·엑셀 일괄 등록은 연결된 팀 파일 자체에 저장됩니다.
팀 파일 쓰기 권한이 없으면 가져올 위치를 개인 저장소로 선택해 개인 목록에만 가져올 수 있습니다.
목록 형식은 기존 schemaVersion:1과 같고, 앞자리0/공백을 포함한 암호와 코드를 유지합니다.

변경이 반영되는 시점
팝업을 열 때, 관리 화면에 다시 포커스할 때, 표시 중인 팀 목록을 주기적으로 갱신할 때 파일을 읽습니다.
로그인을 시작할 때도 worker가 파일을 다시 읽어 해당 시점의 아이디·암호·Bypass Code를 사용합니다.
진행 중인 한 번의 로그인은 일관된 값 묶음을 사용합니다. 변경은 다음 로그인부터 적용됩니다.
OneDrive 앱이 업로드/다른 PC의 다운로드를 완료한 뒤 그 PC에서 새 값을 사용할 수 있습니다.
확장이 OneDrive 클라우드 전송 완료를 확인하는 기능은 없습니다. 동기화 일시정지나 오프라인 상태는 자동 해제하지 않습니다.
같은 파일명으로 교체된 파일은 다시 읽으며, 브라우저가 기존 파일 연결을 잃으면 파일 선택으로 재연결합니다.

동시 편집과 오류
편집/가져오기 준비 뒤 로컬 파일이 바뀌면 이전 내용으로 덮어쓰지 않고 중지합니다.
가져오기는 ‘최신 목록 확인’ 후 다시 시도하고, 계정 편집은 입력을 확인한 뒤 닫고 새로 편집합니다.
파일을 읽지 못하거나 JSON이 잘못되면 이전 암호나 개인 목록으로 대신 로그인하지 않습니다.
브라우저 내부 쓰기를 직렬화하고, 저장 직전에 기존 파일 해시를 다시 비교합니다.
이 검사는 여러 PC의 동시 오프라인 수정을 잠그는 분산 잠금이 아닙니다. OneDrive가 충돌 사본을 만들었다면 원본/버전 기록을 확인하세요.

Brave에서 처음 연결할 때
보조 프로그램이나 Windows 전체 경로 입력 없이 파일 선택으로 연결합니다.
Brave가 파일 접근 기능을 꺼 둔 경우 팀 파일 연결 화면 또는 설정의 ‘Brave 설정 열기’를 누릅니다.
주소창에 직접 brave://flags/#file-system-access-api 를 입력해도 됩니다.
File System Access API를 Enabled로 선택하고 Relaunch로 Brave를 다시 시작합니다.
확장 → 설정 → 저장 위치 → 팀 파일 → 파일 선택 → 같은 OneDrive JSON 선택.
파일은 기본으로 편집 가능합니다. 브라우저의 쓰기 승인은 사용자가 직접 허용합니다.
브라우저 보안 경계 때문에 확장이 이 설정을 자동으로 켤 수는 없습니다.
일반 파일 업로드는 선택 당시의 사본만 읽으므로 자동 동기화의 대체 수단으로 사용하지 않습니다.

1.3.0에서 업데이트
개인 계정, 테마, 기존 파일 선택 연결은 유지합니다.
이전 Windows 전체 경로 연결은 동일 팀 JSON을 파일 선택으로 다시 연결해야 합니다.
원본 파일을 복사하거나 새 파일로 덮어쓸 필요가 없습니다. 기존 보조 프로그램은 더 이상 사용하지 않습니다.

검증 범위
독립 Linux Chromium 프로필 두 개와 File System Access API와 가상 팀 파일을 검사합니다.
실제 OPFS 파일 핸들에서도 저장·해시 충돌·재연결/생성 UI를 검사했습니다. OCI 네트워크/실제 고객 인증은 사용하지 않았습니다.
실제 OneDrive 클라우드 전송과 사용자 Windows의 파일 선택·권한창, 고객 인증은 별도 확인이 필요합니다.

1.3.2 접근 유지와 복구
파일 연결과 실제 접근 권한은 다릅니다. 브라우저의 일회성 허용은 팝업을 닫은 뒤 만료될 수 있습니다.
이 경우 메인 화면에서 팀 파일 열기/Enter로 기존 파일 접근을 복구하며 설정/파일 선택을 반복하지 않습니다.
승인 창의 방문할 때마다 허용을 선택하면 브라우저가 허용한 권한을 다음에도 자동 사용합니다.
프로그램이 브라우저 권한을 자동 승인하거나 설정 파일을 바꾸지는 않습니다. 권한이 없으면 오래된 암호로 대신 로그인하지 않습니다.
https://developer.chrome.com/blog/persistent-permissions-for-the-file-system-access-api
