수정
비로그인 상태에서 www.oracle.com/cloud/sign-in.html 계정명 입력으로 이어지는 공식 경로도 처리합니다. 이 경로에서는 테넌시 이름만 입력하며 다른 Oracle 웹페이지에는 실행하지 않습니다.

기존 OCI 세션이 있을 때 login.oci.oraclecloud.com의 Session Picker에서 멈추던 경로를 처리합니다. 이 호스트의 정확한 선택적 권한을 요청하고, OCI 콘솔/확인된 인증 이동에서 이어진 작업 탭의 최상위 문서만 처리합니다.

Oracle 공개 로그인 자바스크립트에서 session-picker-dialog, btn-session-* 카드와 user-name/domain-name/tenant-name 구조, session-change 버튼을 확인했습니다. 고객의 실제 목록은 테스트/배포 파일에 복사하지 않았습니다. 테스트는 example.invalid 가상 계정을 사용합니다.

세션 카드는 테넌시(대소문자 무시), 아이디와 도메인(앞뒤 공백 외 정확히 일치)이 모두 맞고 하나일 때만 선택합니다. 선택 직전 다시 읽어 변경된 카드이면 중지합니다. 같은 테넌시의 다른 사용자/다른 도메인, 중복 세션은 임의로 선택하지 않습니다. 일치 세션이 없으면 Oracle의 다른 사용자 계정 로그인 버튼을 눌러 테넌시·도메인·계정·Bypass Code 순서로 이어집니다. 이미 유효한 일치 세션이면 비밀번호와 코드를 다시 입력하지 않고 그 세션으로 콘솔 이동합니다.

로그인 게이트웨이에 도착한 것만으로 비밀번호를 제공하지 않습니다. 이 작업에서 테넌시 입력 또는 정확한 세션 선택을 확인한 뒤에만 해당 인증 단계에 값을 제공합니다. 다른 사이트, 다른 탭/문서와 하위 프레임에는 제공하지 않습니다. 기존 Oracle 세션을 로그아웃하거나 관리자 세션 설정을 바꾸지 않습니다.
